# UI 更新实施与验收

根据 [ui-refresh-plan.md](./ui-refresh-plan.md) 实施。

## 已完成

- 淡白页面、灰黑配色、细边框、统一圆角与轻阴影；移除网格背景和蓝绿装饰色。
- 本地 Inter 与 Source Serif 4 可变字体、预加载和字体授权文件。
- 桌面双栏；980px 及以下按专辑导入、评分编辑、海报预览排列。
- 手机端曲名独占一行，其余字段在下一行；按钮与曲目控件触控高度至少 44px。
- 统一悬停、灰色键盘焦点和禁用状态；结果列表轻微交错出现，编辑区淡入，心形切换轻微缩放。
- 支持减少动态效果；预览连续输入时不触发整张海报进入动画。
- DOM 海报等比缩放，封面和圆形评分始终左右排列；海报标题使用衬线字体。
- CSS 中集中定义字体、颜色与海报尺寸，Canvas 通过 `src/poster/theme.js` 读取同一套参数。
- Canvas 测量文字前等待字体就绪；使用柔和封面阴影、细线、统一评分与曲目配色。
- 静态服务仅补充 WOFF2 的 MIME 类型。

## 保留的功能与边界

`src/app.js`、`src/api/itunes.js`、草稿、缓存、校验、格式化、封面请求和 DOM 数据绑定代码保持不变。
PNG 继续固定 1200px 宽，高度随内容增长，文件命名与下载方式不变。
喜欢与总评分 >= 90 的判断条件不变；16/17/22/23 首曲目附近的密度切换条件不变。
`out/` 内已有示例图片未修改；未引入运行时依赖。

保留原来的文本处理规则：预览可自然换行，PNG 标题最多三行、艺人最多两行、简评最多四行，曲名保持单行省略。
因此极长文本的预览高度与 PNG 高度可能不同；字体与主要布局使用相同参数，但并非逐像素截图。

## 浏览器回归

本次验收结果：2026-09-12，Windows 无界面 Chrome，15 组检查全部通过。
已人工查看桌面界面、320px 编辑与预览、搜索选择态及导出 PNG 截图。
核心业务文件已与修改前副本逐字节比对；`out/` 中 7 张已有 PNG 的 SHA-256 均未改变。

先运行 `npm run dev`，再在另一终端执行：

```sh
node tests/ui-refresh.mjs
```

需要 Node.js 22+ 和已安装的 Chrome 或 Edge。脚本自动寻找常用安装路径，也可通过 `BROWSER_PATH` 指定浏览器，
通过 `TEST_URL` 指定已运行的应用地址（默认 http://127.0.0.1:5174）。
脚本使用独立临时浏览器配置，截图、测试 PNG 与报告写入系统临时目录，路径在运行结果中输出。

检查范围：

- 空草稿、隐藏和禁用状态、本地字体资源、键盘焦点。
- 手动创建、字段修改、评分取整与范围、未完成提示、添加和删除曲目、喜欢切换、草稿恢复。
- 1440、1024、981、980、768、390、320px 布局，系统滚动条占宽场景，无页面横向滚动及控件重叠。
- 减少动态效果，连续输入时焦点保持、预览无重复进入动画。
- 0、1、16、17、22、23、40 首曲目；未评分、89、90、100；中英文及长标题、180 字简评。
- Canvas 背景及评分描边像素、1200px 宽、动态高度、正常文本下的预览比例。
- 实际 PNG 下载及文件名；封面成功和失败时 DOM/Canvas 的显示。
- iTunes JSONP 搜索和 Lookup、US/CN/JP 参数、结果选择、空结果、接口失败、清空与刷新。

搜索、Lookup 和远程封面使用浏览器请求拦截提供固定响应，保留真实脚本节点、事件处理与下载执行路径。
这验证应用行为，不代表对 Apple 在线服务可用性或所有浏览器的实机验证。
